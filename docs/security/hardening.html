Hardening baseline

This page is a secure configuration baseline for production deployments of HaltSQL. It is for platform and security engineers who deploy haltsql-server or haltsql-proxy and want one list of settings to review. Each row gives the setting, the recommended value, the reason and the page with the details.

Most defaults are already the safe choice. The rows marked (not default) need an explicit change.

Database​

HaltSQL is one layer of three. A bug in HaltSQL, a policy mistake, or a caller that skips the check is contained only by the database's own controls (defense-in-depth.md).

Policy delivery​

SettingRecommended valueWhyDetails
Policy sourceLoad policies only from signed bundles: policies[].bundle or policies[].bundle_source (not default)The server verifies the Ed25519 signature before it reads a policy, so a compromised file system or delivery channel cannot change thempolicy-bundles.md
public_keysOnly the current signing key, plus the next one during a rotationAny listed key may signKey management
Signing keyGenerated with haltsql bundle keygen, stored as a protected CI secret, never committedWhoever holds it can authorize any policypolicy-ci.md
bundle_source.ociA digest-pinned reference (repo@sha256:...) for immutable deployments, or a tag with monotonic metadata.versionThe poller refuses rollbacks; a digest pins the exact artifactconfig-reference.md
cache_dirSet, on a writable volumeThe server can restart from the last verified bundle while the source is down; the cache is re-verified on every startpolicy-bundles.md

Note: there is no setting that forbids plain path: or inline: policies. To enforce "signed bundles only", review the config in change control, and check that every policy in GET /v1/admin/status has origin: bundle_source (or bundle_or_file for local bundles).

OPA​

SettingRecommended valueWhyDetails
opa.on_errordeny (the default)An unreachable or misconfigured OPA must not allow queriesopa.md
opa.urlA loopback sidecar, or https with tls.ca_filePlain http is accepted only for loopbackconfig-reference.md
opa.headersA bearer token from a secret placeholder, with OPA's own authentication enabledStops other workloads from changing OPA's answersopa.md

OPA can only add denials: a query HaltSQL denies is never sent to OPA, and no OPA answer turns a denial into an allow. There is nothing to configure for this.

Checking a deployment​

  • haltsql config show --config FILE prints the effective configuration (flags, HALTSQL_* environment and file merged) with secrets redacted.
  • GET /v1/admin/status shows loaded policies, their origin and mode, bundle signer key ids, audit sink health and the OPA settings.
  • haltsql-proxy validate -c FILE --json prints the proxy's effective config with secrets redacted.
