HaltSQL documentation

HaltSQL is a policy firewall for LLM-generated PostgreSQL. It checks whether an exact SQL string is allowed for a caller under a declarative policy, and returns a verdict with machine-readable reasons. It never rewrites SQL and never connects to the database.

These docs describe version 0.0.1 (pre-1.0). The verdict format and reason codes are stable; other interfaces may still change. See Versioning and upgrades.

Features​

  • CLI: every haltsql command, flag and exit code.
  • HTTP API: the haltsql-server sidecar (OpenAPI 3.1).
  • Wire proxy: haltsql-proxy, the PostgreSQL wire-protocol firewall.
  • Signed policy bundles and Policy CI.
  • Shadow mode reports: what would have been denied, and conservative policy suggestions.
  • Open Policy Agent: an optional deny-only decision after HaltSQL allows a query.
  • RLS generation and Schema and PII import.

Document kinds at a glance​

Everything HaltSQL reads is YAML or JSON with apiVersion: haltsql.dev/v1 and a kind:

KindPurposeReference
PolicyWhat SQL is allowedpolicy-reference.md
ConfigHow the CLI and server runconfig-reference.md
TestSuiteAllow/deny test cases for a policytesting.md
CatalogSchema snapshot (tables and column types)policy-reference.md
ScenarioEnterprise lab scenariotesting.md
ProxyConfigHow haltsql-proxy runsproxy.md
PolicyBundleSigned set of policies (canonical JSON + .sig)policy-bundles.md

haltsql validate FILE... checks Policy, Config, TestSuite, Catalog and Scenario documents; haltsql-proxy validate --config FILE checks a ProxyConfig, and haltsql bundle verify checks a PolicyBundle. haltsql schema export writes JSON Schemas for editor autocomplete.
